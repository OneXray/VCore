# N7：选定 VLESS 高级安全能力

日期：2026-09-27。状态：**N7 本地阶段签收 PASS。** 本轮按确认范围
保留 VLESS Encryption、混合 REALITY、JLS，新增静态 ECH；取消未开放的
ShadowTLS，Restls 不恢复，动态 ECH/宿主 bootstrap 后置。当前 Invoke API v5 /
schema27，不称“完整 VLESS”或任意组合均通过。

## 交付与边界

- 主腿和 XHTTP 独立下载腿静态 `ech-opts.enable/config`；整对象继承、替换、
  显式清除及严格互斥。启用必须带显式 ECHConfigList，未知动态查询字段拒绝。
- 普通 TLS/QUIC 使用官方 rustls + ring 和官方 Rust HPKE 公开 Adapter；
  命名指纹使用原有 boring ECH 接口。本轮没有修改第三方或 boring fork。
- TLS 1.3、真实 ECH accepted 才交付业务流；拒绝不发送业务或客户端证书，
  不自动重拨/回放、不采用 retry config、不降级。静态 ECH 禁用 TLS 恢复/0-RTT。
- 仅 X25519/HKDF-SHA256 与三种 AEAD；不会扩展 SS 的 AWS-LC 例外。完整配置与
  rustls/boring 拒绝证书处理差异见 [静态 ECH](../../ech.md)。
- JLS 保持已签收范围。未指纹 gRPC 的关闭参照仍是明示的 Mihomo Chrome 路径，
  不称完全同配置对照；该原始失败与理由见 [JLS 历史记录](N7-jls.md)。
- Safari ECH 的 gRPC 关闭参照同样明示为官方 Chrome + 同一 ECH listener；
  Mihomo Safari 本身在 ECH 握手报错，VCore 的实际消费者保持 Safari。
  该参照只比较传输关闭，不宣称双方同指纹；原始失败保留在进度记录。

Encryption、混合 REALITY、JLS 的历史完整子包分别见 [N7.1](N7-encryption.md)、
[N7.2](N7-reality-hybrid.md)、[JLS](N7-jls.md)。本轮已重新运行保留组合与共享
回归，未将历史成功拼成当前阶段成功。详细开发失败保留在 [进度记录](N7-progress.md)。

## 对端与隔离

普通传输优先官方 latest Mihomo，H3 使用官方 latest Xray；packetaddr、sing-mux
及对应 Encryption 明示为 Xray transport → Mihomo VLESS 分层解码。HTTP/H2/
扩展 WS 的 ECH 使用 Xray TLS 网关 → 官方 V2Ray transport → Mihomo VLESS；
网关通过官方 `XRAY_BUF_SPLICE=disable` 保留响应 TLS 封装。没有直接宣称
V2Ray 支持 ECH，也没有编写或修改第三方协议服务器。

所有网络原站、服务器、观察器和官方对照入口都位于本次所属 Apple Container
host-only 网络，guest MTU 1500。无宿主服务端后备、发布端口、路由/DNS/防火墙
更改或关闭 Mihomo 回环保护。官方 latest 下载一次冻结用于同一完整运行，
实际版本与二进制/下载包摘要以该轮报告为准。容器镜像也每轮在线刷新一次，
