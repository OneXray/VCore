## 行为与版本决策

通过生产公开 `XHttpClient::connect(BoxStream)` 注入受控 HTTP/2 对端：同一次写入依次发送响应头、带 END_STREAM 的 DATA 和 RST_STREAM(CANCEL)。旧版实际报 reset，未交付已完成的响应；升级后完整数据被保留。另验 DATA **不带** END_STREAM 时的 CANCEL 仍以 typed h2 error 返回，不能把截断或取消吞成正常 EOF。

这是恶意帧 fixture 的定向回归，不冒充原生服务端互通，也不改变 Mihomo 对齐的 XHTTP 整逻辑连接关闭契约。应用 `shutdown()` 与对端已完成响应后发送 RST 是两个不同事件。

[官方 changelog](https://github.com/hyperium/h2/blob/v0.4.19/CHANGELOG.md)列出了 0.4.16–0.4.19 的响应关闭、流控、唤醒与资源修复。保留 0.4.19 的默认小 DATA 帧预算：按初始连接窗口的一半计算，最小25,600 bytes，耗尽关闭连接；没有关闭保护或配置无限预算以使测试通过。[公开 Builder 契约](https://github.com/hyperium/h2/blob/v0.4.19/src/client.rs)。既有 XHTTP 的小帧让出、三模式关闭及独立下载回归均通过。

本次仅更新主锁和流实验锁中的 h2；其他两个路径依赖实验原锁已经是0.4.19，保持原样。N0-B 的0.4.15历史报告不改写为新版结果。
