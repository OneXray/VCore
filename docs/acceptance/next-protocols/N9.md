## 资源观察口径

同步 Invoke scope 显式继承到引擎线程及自有子任务；八类计数分别是 task、
socket、session、association、reassembly、pool、waiter、handshake。
scope 可嵌套、panic 时恢复，不使用全局计数重置；生产构建为零大小 guard，
不携带测试计数器。不宣称逐个统计第三方库内部任务；其归属通过受控连接与
同步 Stop 检查，FD 为独立交叉观测。

SOCKS UDP/HY2 UDP/QUIC入队/出队四类记录单队列占用高水位，容量16/32/32/32，
已保留发送许可计入占用。不是所有队列容量之和，也不是当前活对象计数。
无新增生产限流、排队容量或阻塞策略。

40-flow 进程在空 Tokio IO driver 初始化之后固定FD基线：进程级 Unix 信号
管道可存续，不用协议预热掩盖泄漏。生命周期测试 Stop 当时仍持有的测试客户
端/原站观察FD逐轮声明，释放夹具后必须回到原基线。5秒静默不是清理宽限。

macOS `malloc_zone_statistics(NULL)` 读取在用堆，RSS另列，不读取分配内容。
后10样本堆中位数增长≤max(1MiB,5%)，八类活对象与FD晚期峰值不高于早期；
末轮40-flow建链中位数≤首轮2倍。不将节流运行数据称为公网/最大吞吐基准。

## 失败、修复与保留边界

- 开发轮 SS→SS 的10MiB回包超时保留。有界内存用例复现调用方在 Pending 后
  扩大缓冲时，官方 codec 保留旧加密帧但报告新输入长度，产生确认字节丢失。
  仅修改自有适配器：最多保留一个16KiB原文块，固定重试长度，flush/shutdown
  排空且不阻塞反向读取。三算法、两种首次输入尺寸回归；未修改官方库。
- AnyTLS 活动会话复用和 `MATCH,REJECT` 两个早期夹具假设与既有契约不符，
  已修正夹具；没有改变路由或池策略迁就测试。
- SS EIH 4096字节UDP被官方 ssserver默认禁用IP分片策略拒绝，真实日志为
  `Message too large`。夹具开启官方两向分片选项，MTU仍1500，不改第三方。
- Cargo全目标检查曾将辅助模块识别为独立测试，移动到既有测试子目录后重跑。
- 最终候选v1的五个本地门禁通过，随后 AnyTLS→VMess 的小流能力用例首响应
  超时，整轮仍为FAIL。独立最小用例重现；原因是测试直接写缓冲流后未刷新，
  只为测试调用方补齐flush，最小与完整原始组合均通过，生产VMess未改。
  v1及red/green原始记录保留，v2从头运行，不拼接v1的本地或组合成绩。
- 最终候选v2在第46组 VMess→SS 的首个服务器先发路径失败（10秒首包EOF）；
  单组合重复同样失败。公开 connector 的最小内存回归在缓冲上游中超时，
  去掉缓冲立即通过，恢复缓冲再次超时：SS 内部空首写未刷新到底层，不能
  等待不存在的应用写入代为刷新。自有适配器新增可续写的 EmptyFlushing
  状态；三算法回归、原空首写/半关闭检查及原始实际组合通过，第三方和
  VMess 生产实现均不改动。v2保留为FAIL，后续从头运行v3，不拼接45组成绩。
- v3的五个本地门禁、49组两跳、九个运行时门禁（包括完整1800秒）通过，
  但独立 IPv6 明文随机跳端口窗口在UDP sequence=732、size=4066的回包超时；
  其余三个HOP窗口通过。四组均清理完成，v3整轮仍为FAIL，共享回归未执行。
  更密集的独立原生窗口随后捕获四个回包分片被自有completed-ID缓存全数
  拒绝：官方端随机复用了16位ID。公开 connector 的固定ID内存回归有效
  red/green 已完成，修复移除完成后的ID屏蔽，与Mihomo交付后清空状态一致；
  未完成分片去重/冲突、来源/容量/过期检查保留。这不是官方缓冲上限或
  N6旧接收窗口问题；v3保留FAIL，修复后由v5重新完成全部门禁。
- Trojan域名UDP沿既有Mihomo listener缺口，用相同首跳加Xray末跳补验；不把
  其他Mihomo失败自动替换对端。EIH证明单层原生多用户终结，不证明任意多层
  身份中继或独立密码实现正确性。
- v4 的五个本地门禁通过，但官方Hysteria的容器内防火墙工具包准备未完成，
  49组合及后续业务门禁未启动。所属准备容器已清理；原内部异常只有类型，
  不臆测具体网络原因。独立全新准备随后通过，源码不变，新建v5完整重跑，
  v4保留FAIL而非复用其本地成绩。
- [SS上游padding风险](../../shadowsocks.md)仍按已接受边界保留；本次写入适配
  修复与该风险不同，不宣称安全缺陷已修补。既有原生关闭参照差异仍按N4/N7
  明示例外，不恢复“非XHTTP必须收到半关闭尾包”要求。
