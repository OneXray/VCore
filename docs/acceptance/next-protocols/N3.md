## 交付范围

- VMess AEAD 请求/响应认证，仅标准 UUID 与 alterId=0；AES-128-GCM、ChaCha20-Poly1305、none/zero、硬件能力 auto，适用的 padding/认证长度四种组合。
- TCP、WS、gRPC、HTTP 首包伪装、legacy H2，分别支持明文与标准 TLS。复用共享 Dialer、TLS、流适配器和运行时，不引入协议专属 socket 工厂。
- raw、XUDP、packetaddr：三种目标类型、独立收发预算、有界帧、受控 DNS、来源/关联隔离、发送取消立即释放 IO、增量读取取消恢复。
- 严格公开 YAML、具体与嵌套 select 上游、DIRECT/REJECT、一次建链快照、HTTP/SOCKS5/模拟 TUN、IPv6、DNS 出口、node-only 测速和同步 Stop。
- 默认、TUN、标准发布 feature 包含 VMess；Invoke API v5 不变，内部 schema 16。配置不接受 YAML 内的 schema 字段。契约见 [VMess](../../vmess.md) 和 [配置](../../config.yaml)。

没有修改第三方源码、升级依赖或变更 rustls provider/fork；现有 TLS 安全边界和已批准的依赖例外不变。Hysteria2/WireGuard YAML 仍未开放，VLESS 后续能力不由本阶段抵扣。

## 开发中发现的问题与保留记录

- `n3-public-smoke-20260924-v1`、`n3-public-udp-max-20260924-v1` 保留 15000 字节回包超时。单包缩减与临时诊断 `n3-public-udp-max-diagnostic-20260924-v1` 证实 macOS SOCKS UDP 回送 socket 返回 EMSGSIZE，而容器原站已收到完整数据。修复只设置 VCore 自有 SOCKS UDP socket 的发送缓冲为已声明 wire 上限+1；不修改宿主 sysctl 或第三方。小包对照与修复后的原用例分别有记录，临时诊断已删除。
- 代码复核后增加半帧发送取消测试，raw/packetaddr 原实现等待下一次调用或 Drop 才释放 IO，定向测试以 `cancelled VMess packet send retained IO` 失败。改为发送 future 持有流、仅成功后归还，和共享 XUDP 一致；三个编码的定向测试均通过。
- `n3-acceptance-20260924-v1` 为同步脚本文档与关闭历史宿主入口而由代理主动 SIGINT 中断；`v2` 为补齐上述取消修复主动中断，已创建的两个容器均停止并删除。两次都不是签收结果，不把中断记为协议失败或 PASS。
- `n3-acceptance-20260924-v3` 的 109 组原生用例全部通过，57 个容器全部清理，但共享 TLS 测试使用了错误的 Rust 模块筛选路径，命令退出 0 却执行 0 项测试。结构化事件门禁拒绝缺少的 13 项断言，该轮保持 FAIL；更正为实际 `security::tls::tests::` 后，13 项定向测试全部通过，再重新执行完整整轮。同时修复独立 coverage 入口的相对路径归一化，离线回归先红后绿；未修改失败记录或降低门槛。
