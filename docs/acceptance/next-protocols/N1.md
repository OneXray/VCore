## 原生与旧协议回归

9项原生传输：Mihomo WS/WSS/gRPC/gRPC-TLS/默认ED；V2Ray HTTP首包/legacy H2/自定义ED头/路径ED。每项验证服务器先发、65,536字节逐字节回显、14字节响应尾部、origin完成/仅接受一次、protect一次、driver join及已观测资源为0。该套探针没有执行真实客户端half-close，`close:false`明确保留；关闭语义由定向/N0差分证据承担，不能把接收尾部改称原生半关闭通过。

## 预检缺口与失败保留

独立全对端预检`target/interop/runs/n1-4xv7t14i/`非零，原因仅W环境：Apple Container Linux6.18.35，当前alpine发行工具`wireguard-tools v1.0.20260223`已安装，但`ip link add n1-wg type wireguard`返回`Error: Unknown device type.`。内核WG未就绪，后续内外双栈未执行；W项记录`cleanup:true`，只清理自建VM，没有改宿主路由/VPN。总预检不是N1业务PASS，也不把此缺口扩散为M/V2失败。

镜像index摘要为`sha256:294b683cb724975bec92580e1e685676bd4b50bda910ddb8c51d4cabeaec77e6`，ARM64变体`sha256:260479a1cfaf304c4c20da7f8405d3ce313513dcd534bb743257bdd2fe0f3e2d`。解除W阻塞需要支持WireGuard的隔离内核，或按官方wireguard-go路线满足TUN/权限/双栈；不能用客户端库自连冒充原生服务端。只影响依赖W的N8，不影响本轮N1公共机制。

较早预检`n1-xl2buv6d`保留了同一失败，后一次新增具体阶段/错误与精简镜像身份，不覆盖首轮记录。`n1-as3c_r1n`是更早源码的21组通过，`n1-lli0w8gh`只是单组QUIC通过；本次签收用最终`n1-9jaudb1t`，不把单组或较早源码结果挪用为最终输入。

## N6带宽实验参数冻结（尚未执行）

以下是后续验收规范，不是N1已测吞吐：受控原生H/M单向饱和流，按有效应用字节计数，负载分块64KiB并校验序号/内容；上下行分开，预热10秒后采样30秒，每秒一桶。速率使用十进制bit/s，预设1,000,000与2,000,000 bit/s；不限速基线必须至少6,000,000 bit/s，否则环境不具判定能力，不能放宽容差。

固定限制分支的30秒平均有效吞吐不得超过扣除实测协议开销后有效限制的110%，较高档有效吞吐至少为较低档1.5倍；分别覆盖客户端限制、服务器更低上限、自动/ignore-client-bandwidth分支。自适应且不承诺固定线速的分支只断言协商/控制器选择和持续传输。必须记录配置协商值、选用ControllerFactory、pacing/发送字节计数、丢包/RTT、实际wire与应用字节；确定性时钟测试只补充算法证据，不替代原生数据闭环。
