### WireGuard / Linux 权限

实际建立并销毁了两个唯一命名、带 `purpose=vcore-next-protocol-preflight` 标签的一次性 VM；镜像为 `alpine@sha256:fd791d74b68913cbb027c6546007b3f0d3bc45125f797758156952bc2d6daf40`。

1. 只读 host-only VM：Linux 6.18.35；`CONFIG_WIREGUARD` 未启用；`CONFIG_TUN`、nftables/NAT 已启用，`/dev/net/tun` 存在。默认 capability 不包含 NET_ADMIN。
2. 单独临时 VM：只增加 `NET_ADMIN`，使用发行版包管理器安装 `wireguard-go 0.0.20250522-r9`、`wireguard-tools 1.0.20250521-r1`、`iproute2 6.17.0-r0`、`nftables 1.1.5-r2`，没有自行修改这些包。使用 default VM 网络仅为取得发行版依赖，未发布宿主端口。
3. `wireguard-go wg-n0`、`ip -details link show wg-n0`、`wg show wg-n0` 成功；它是用户态 TUN 路径，不是内核 WireGuard。工具的泛化提示不能推翻内核配置证据。
4. 删除本次 `wg-n0` 接口后，容器 `--rm` 完成清理。没有改宿主 VPN、路由或网络接口。

结论：**wireguard-go 原生环境启动可行；内核 WireGuard 路径不可用。** 尚未配原生 peer/隧道地址/路由、没有 VCore握手或业务数据，N0-G 官方 peer 数据门禁仍 NOT RUN。Hysteria 单实例多端口 nftables 规则及业务跳跃也未执行；具备内核能力不等于跳跃用例通过。安装路径依据[WireGuard 官方说明](https://www.wireguard.com/install/)。
