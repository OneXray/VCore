# 服务端测试隔离规则

自 2026-09-23 起，**后续所有服务端测试均在隔离容器中执行**。本文件是服务端测试部署方式的权威规则，优先于历史脚本和验收记录中的宿主运行说明。

## 范围

- 协议服务端（Mihomo、Xray、V2Ray、Hysteria、Shadowsocks、WireGuard 等）、UDP echo / TCP / HTTP / DNS 测试原站，以及故障注入中的服务端角色，全部容器化。
- 对照客户端若提供 SOCKS/HTTP 等测试入口，该入口也放在容器中。宿主只运行待测客户端、测试驱动和只读观察工具。
- 纯内存、编解码、离线配置或 mock 单元测试不属于外部服务端互通测试。不能把宿主网络服务改称 mock 来规避隔离。
- 尚未完成容器化、容器不可用或平台不支持的服务端用例记为 `BLOCKED` / `NOT RUN`，不得回退到宿主启动。Linux 测试对端不代表 VCore 新增 Linux 产品支持。

## 执行要求

1. 使用本次任务独占、可识别所有权的容器和私有网络。macOS 使用 Apple Container 的 host-only 网络；不发布宿主端口，不改宿主 VPN、路由、DNS 或防火墙。
2. 协议对端使用官方最新稳定发行二进制，通过官方 `latest` 下载链接获取；不查版本 API、不本地编译、不修改第三方源码、不静默复用旧缓存。镜像使用官方稳定标签，在当次运行记录解析后的 digest。记录容器内实际版本、二进制和下载包校验值。
3. 保留 Mihomo 回环保护和第三方默认 socket 行为；不能通过关闭保护、放宽数据正确性/超时或重试业务包掩盖失败。
4. 原站和协议对端的地址必须来自本次容器网络。配置、证书与测试凭据仅放临时目录，fixture 只读挂载，日志保持有界且脱敏。
5. 注册清理后再启动资源。成功、失败、超时、SIGINT 和部分启动都必须停止并删除本次拥有的容器，检查剩余资源；不得停止或清理其他任务的容器。
6. 报告分别记录隔离拓扑、真实流量结果、源码身份和清理结果。基础设施/清理失败不能记为互通通过；定向诊断通过不等于阶段签收。

历史宿主测试保留为历史证据，不追改为容器测试。旧脚本即使有 `--container`，若原站或反向服务仍在宿主，也不满足本规则；迁移前不得用于新的服务端验收。
