# SOCKS5 代理入站

SOCKS5 与 HTTP、TUN 共用规则、DNS、代理组和出站图；入口不提前解析业务域名。协议遵循 [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928) 与 [RFC 1929](https://www.rfc-editor.org/rfc/rfc1929) 的 CONNECT、UDP ASSOCIATE 和用户名密码协商。

## 配置与监听

- 顶层 `socks-port` 省略或为 0 时关闭，1–65535 时绑定同端口 TCP 与 UDP。
- HTTP、SOCKS5、TUN 至少启用一个；纯 SOCKS5 可以独立运行，并使用代理组 Controller、DNS 和 GeoData。
- `authentication`、`allow-lan` 与 HTTP 共用。默认仅回环且免认证；非空认证必须恰好一项 `user:password`，用户名和密码分别为 1–255 UTF-8 字节，按首个冒号分隔。共享必须配置认证，凭据和共享开关必须有启用的 HTTP 或 SOCKS5 入口消费。
- `ipv6: false` 只绑定 IPv4；true 时增加独立的 IPv6-only socket。仅系统明确不支持该地址族时可省略 IPv6，其余错误使启动失败。
- 所有入站和 Controller 完成绑定后才开始服务。HTTP/SOCKS5 TCP 端口冲突、必要的 UDP 端口冲突均整体回滚。
- 用户名密码协商没有传输加密；共享只适合受信任网络。Controller 的回环和 Bearer 认证不随共享开关改变。

## TCP 与授权

仅 SOCKS5；按当前配置选择免认证或用户名密码方法，不降级绕过已配置认证。握手使用精确读取，保留紧随 CONNECT 的业务字节。认证失败不建立上游。

CONNECT 将 IPv4、IPv6 或域名目标交给共享 Dispatcher；只有上游建立成功才返回成功，拒绝、不可达、超时等使用 SOCKS5 回复码。双向转发支持半关闭，每方向复制缓冲区 4 KiB。

## UDP 关联

- 一个成功协商的 TCP 控制连接拥有一个关联；未授权 UDP 不创建状态或上游。
- 请求的源 IP 必须为未指定地址或 TCP peer IP，不能把代理用于其他来源。回复使用接受到的 TCP 连接的具体本地 IP 和配置端口，即使监听器绑定通配地址，也不返回不可达的通配 relay。
- 用 TCP peer IP、IPv6 接口作用域（scope）与客户端 UDP 源端口识别关联；作用域取自 TCP peer，不从客户端请求推断。请求源端口为 0 时，首个合法且成功入队的同作用域 UDP 包学习端口；同 IP、同作用域至多存在一个尚未学习端口的关联，新的歧义请求被拒绝。同 IP、同作用域的不同明确端口可并存，同端口不能重复授权；不同作用域的相同链路本地地址互不串包。
- 每个关联可转发多个目标，分别经过共享路由；回包保留出站提供的实际远端地址。
- 非零保留位、分片、非法地址、零目标端口和超长报文被丢弃；无效包不学习端口、不延长空闲时间。
- TCP EOF、错误、停止或关联过期撤销授权。源端口可以重新授权，但旧任务不能删除新关联或发送旧代次回包。

这比 mihomo 的共享 UDP 接收策略更严格：UDP 必须归属于仍然有效的 TCP 控制连接，不因收到任意 UDP 包隐式创建关联。

## 边界与回收

| 项目 | 固定上限 / 策略 |
| --- | --- |
| 协商 | 10 秒；方法和用户名/密码各最多 255 字节 |
| TCP 建链、UDP 建链/单次发送/回包写入 | 15 秒，整个操作随所属连接取消 |
| 单关联待发队列 | 16 包；满队列丢弃当前包，不阻塞其他客户端 |
| UDP 入站 wire 大小 | 65,507 字节；接收额外一个 sentinel 字节识别截断/超限 |
| UDP 回包业务负载 | 保守预留最大 262 字节 SOCKS5 头，最多 65,245 字节；嵌套出站继续逐层计算封装预算 |
| 关联空闲 / 检查间隔 | 30 秒 / 10 秒；只有成功入队和成功发送的合法回包刷新时间 |

没有全局业务连接或关联数量准入限制。全局 UDP 接收只做有界解析和非阻塞入队，慢建链和写入留在各关联任务。控制连接拥有该任务，Stop 取消并等待全部 TCP 控制、relay 和 UDP 接收任务，返回后监听端口可以重新绑定。TUN 仍使用其独立 MTU 预算；Controller 流量统计不包含 SOCKS5 数据。

独立 `inbound-socks5` feature 可在不启用业务 HTTP 的构建中使用；默认和 TUN 构建包含两个客户端代理入口。验证范围见 [验收矩阵](acceptance.md)。
