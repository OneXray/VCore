# Domain docs

Layout: single-context.

Before exploring or designing:

1. Read [CONTEXT.md](../../CONTEXT.md) at this repository's root.
2. Read the ADRs under [docs/adr/](../adr/) relevant to the task.

If either is absent, continue without creating placeholders. Domain modeling
creates terminology and decision records when they are actually resolved.

Use the glossary's terms in code, tests, issues, and proposals. Flag genuine
terminology gaps for domain modeling.

If a proposal conflicts with an accepted ADR, identify the ADR and explain
why it should be reconsidered before changing that decision.
